4. How the eBay Sandbox connection works

If a tester selects Connect eBay, the application redirects the tester to eBay's Sandbox authorization page. eBay handles sign-in and permission approval; the application does not request the tester's eBay password.

On successful authorization, the application exchanges the authorization code for access and refresh tokens, encrypts those tokens before storing them with the test workspace, and uses the access token to request a limited inventory preview (up to ten items). The feature is read-only and does not create purchases or modify listings. A temporary HTTPS callback tunnel may be used for local Sandbox tests.

The tester can choose Disconnect in the application to remove the locally stored eBay connection tokens. Tester authorization may also be revoked separately through eBay account permissions. OAuth attempts use short-lived security state; the application should be reviewed before allowing external test participants or production accounts.

This version does not enable eBay Production. Before enabling production access, the operator must meet eBay's applicable marketplace-account deletion/closure notification requirements and review any buyer/order-data processing. eBay processes its own account and authorization data under its own privacy terms.

6. How long is information retained?

Information is kept only while needed for a specific development/testing purpose or an applicable legal requirement. The following describes the implemented technical behavior or retention criteria rather than promising deletion functions that have not been implemented:

  • Authentication sessions: sessions expire after seven days; logout revokes the active session. Expired session records may remain in the development database until maintenance or deletion.
  • Account and workspace data: retained while the related test account and development database are in use; deletion is handled by the operator upon a verified request where applicable. The current prototype does not advertise a self-service account-deletion feature or a fixed automatic deletion schedule.
  • eBay connection tokens: deleted from the application's active connection record when the tester disconnects. Short-lived OAuth state is valid for ten minutes, though related technical records may remain until database cleanup.
  • Inventory preview: requested for display; the current preview feature is not designed to persist the returned inventory item list as synchronized listings. Standard operational logs or local browser state may still retain limited technical information.
  • Transactional email delivery history: the configured cleanup period in the existing development application is 90 days for completed delivery records, provided the cleanup worker runs. Pending and other operational records may remain until handled.
  • Stripe test billing data: identifiers and event references may remain in the local development database until test data is cleared, subject to any applicable legal obligation.
  • Logs and backups: retention depends on the actual local runtime and any backups created by the operator; no universal automatic log or backup deletion period is asserted for the prototype.

7. Security measures

The development application uses hashed passwords, session-based authentication, access controls for workspaces, anti-forgery checks for protected actions, and encryption for eBay OAuth tokens at rest. The eBay Sandbox callback uses HTTPS through a controlled development tunnel. Access to local development files and any backups is the operator's responsibility. No service can promise absolute security, and these measures do not replace a full security review before production deployment.

8. Cookies and similar technologies

The local application uses an essential login session cookie named rr_session, configured with a maximum age of seven days, to keep a tester signed in. It is intended for authentication and security rather than behavioral advertising. The privacy page itself contains no custom analytics scripts, tracking pixels or advertising cookies. GitHub Pages and other external services may process technical data or use their own technologies under their privacy notices.

The operator does not currently use the project to send marketing emails or to build advertising profiles of testers. If non-essential analytics or marketing trackers are introduced, additional disclosures and, where legally necessary, a prior consent mechanism will be added.
